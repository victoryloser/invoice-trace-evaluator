# 方法与实现说明

本文件说明状态重建、业务判定、根因归并及评分规则。仓库不提供业务数据；接入时由用户提供实际金额、配置税率和企业上下文。程序仅实现文档所述的开票流程，不能通过任意自然语言规则扩展为其他业务。

## 判定流程

1. `loader/models` 严格读取逐行 JSON，校验必需事件字段、类型、时区、唯一 Case/run/event/seq 及归属。错误携带物理行号；事件按原 `seq` 分析，原文件和原编号不改写。
2. `state` 从用户请求和 context 构造入口目标，保存值、来源、出现时点及覆盖关系。context 汇总的多轮历史在入口生效；轨迹中的 `user_update` 在对应事件到达时生效。`reference_result` 用于终态对照，不倒灌早期目标。
3. `rules` 实现 I01/E01/F01/A01/A02/P01/B01/U01/C01/R01/R02/R03/T01/O01。使用 Decimal 和 ROUND_HALF_UP；先按实际输入复算，区分算术错误与错误口径的正常传播。批量明细比较内容及重复次数。
4. 语义仍不明确时调用 Judge。模型只接收当前 run 的匿名事件前缀、上下文及目标；版本、Case/run 和事件编号被替换。标签、业务相关字段路径及首错时点由程序核验。`decisions` 保留确定性事实、记录冲突，并将未解决语义对应检查标为 unknown、已确认语义违规同步为 fail。模型决定可支持的语义结论，程序决定分组与扣分；路径相关性不是一般自然语言蕴含证明。
5. `attribution/scoring` 保留独立约束错误，合并相同来源的重复观察。因果连接要求实际字段/金额保留，不依赖事件相邻。每组取最高适用分值，最后分数截断至 0。判断正确性不靠分数阈值。
6. `export` 校验全量覆盖、输出 Schema、同 run 证据、首错、扣分唯一性和算术；全量成功后发布结果。`report` 只读取产物，单条有效但尚未配对的运行也纳入统计；已知候选违规不会因另一条未知而降为仅待调查。时间线可查看每步状态、来源及根因链接。

## 金额与业务状态

不含税金额：税额 = ROUND_HALF_UP(金额 × 配置税率, 2)；含税金额：先以 1+税率反算不含税金额并舍入，再以差额算税额。批量不同商品分别按其配置税率计算并合计。

确认来源包括输入中的 `context.user_confirmation_recorded` 和扩展轨迹的 `observed_input.user_confirmation`。数量、金额、购方等用户修订使旧确认失效。预览内容有派生指纹，但不要求原始材料具有新增字段。

正确等待确认、正确拒绝重复、正确停止未知受理重试、如实处理外部失败均可判处理正确。轨迹记录出票取输入摘要和记录中的服务回调，不由 Agent 宣称成功推断；记录冲突进入复核。这些来源尚未经过独立外部查询，不能解释为真实业务系统已核验，详见 [出票证据与核验边界](business-evidence.md)。

轨迹截断可能使提交步骤和根因不可见，但明确回调与确认状态仍能证明违规及出票事实。此时保留 `INSUFFICIENT_EVIDENCE`、空首错、已知双布尔和有规则依据的扣分。只有未知根因本身不扣分；业务结果仍未知时不发布有效结论。

## 阶段与证据

`StageResult.status` 仅表示评测器阶段执行情况；`checks.status` 表示业务规则；输出中的两个布尔表示被评 Agent 结论。这三层不相互替代。检测出错误时规则阶段仍可以成功。非必需 Judge 的 skipped 不计为有效模型判断。

原始输入 hash、流程/业务规则/Schema hash、源码 hash、依赖锁 hash、配置及提示词 hash、模型模式和参数都在 manifest 或 Judge 记录中。字段证据路径、预期值和实际值在 findings 中；阶段日志的 `eval_event_seq` 不是被评事件编号。

默认规则评测不联网。语义判断由配置的模型执行，缓存用于复现已记录的响应；稳定性检查区分缓存命中与重新请求。

## 评分与版本门控

| 规则 | 每个独立因果组扣分 | 维度 |
|---|---:|---|
| C01/R01/R02/R03 | 50 | RISK_CONTROL |
| I01/E01/F01/A01/A02/P01/B01/U01 | 30 | BUSINESS_RESULT |
| T01 | 30 | TOOL_CALL |
| O01 | 40 | BUSINESS_RESULT |

实际版本位序采用输入 `runs` 的基线、候选顺序，改变显示版本名称不影响规则。首先比较严重风险类型集合：严格子集更优；新增不同类型风险时不强行排序。风险相同再比较处理正确性与分数。

候选存在严重风险或未修复错误为 defer；关键 unknown 为 investigate；当前范围正确但独立覆盖不足为 gray；只有预登记必测 Case 全覆盖、候选全部正确、没有未解释退化且独立回归已通过才可 release。门控读取验收证据文件，校验内容摘要、源码、判定配置（不含门控文件路径）、业务规则与 Schema、预登记时间、独立人工声明及逐 run 期望；布尔配置不能代替证据。门控只覆盖已登记的输入范围。独立性来自外部审核人的声明，程序无法自行证明人的身份与独立性。

## 多根因核对与验收

根因配对先在完整列表中保留所有“标签＋首错”精确匹配，再按原事件 seq 对同标签余项配对，避免局部贪心抢占精确匹配。取消类意图/上下文错误也计入高风险漏报。双 Judge 使用全部根因数组，保留相同标签的独立错误，区分漏项、额外根因、定位和证据差异。

`stability --fresh` 跳过缓存读写，以全部必要判断为有效率分母；完整响应不同与业务结论不同分别计算。人工复核模板绑定评测 manifest 和原结论，导入时不允许替换复核对象，未审项保留待审状态。独立回归采用先登记输入及期望、后执行、再核对的顺序，流程见[验收与复核](review.md)。
